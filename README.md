# Futu 美股量化交易系统

基于富途官方开源 Python SDK `FutunnOpen/py-futu-api`。系统默认使用
`US + SIMULATE` 模拟盘；实盘能力仅作为受控接入框架存在，必须经过独立页面配置、策略白名单、
额度限制和短时人工确认会话才可能提交真实订单。当前提供账户权益、持仓、今日/历史订单、
基础股票信号、组合级“核心—卫星”策略、财报 Gamma、波动率期权和期权组合执行能力。

## 前置条件

1. 安装并启动 Futu OpenD，使用富途账号登录。
2. 在富途客户端创建/确认美股模拟账户。
3. OpenD 默认监听 `127.0.0.1:11111`。本项目不需要 API key；认证由 OpenD 登录会话负责。
4. 如果未来连接实盘，真实交易解锁必须在富途 OpenD 或富途客户端中完成；本系统不保存富途交易密码。

## 安装与配置

```bash
cp .env.example .env
uv sync --extra dev
```

如有多个模拟账户，把目标 `acc_id` 写进 `.env` 的 `FUTU_ACC_ID`。不要把 `.env` 提交到 Git。

## 验证连接

```bash
uv run python scripts/check_connection.py
```

看到 `OK` 和 `SIMULATE` 后说明模拟盘连接成功。

## 研究数据与回测 V2

侧边栏“研究与系统 → 数据研究中心”提供多源历史补全、数据目录、来源交叉校验和回测 V2。
富途仍是主历史源；Alpaca 和 Yahoo 只用于研究补全，不会进入实时下单定价链。没有配置第三方
凭证、没有安装可选依赖时，账户面板、雷达、统一交易服务和模拟盘下单均不受影响。

启用 Yahoo 三级备用：

```bash
uv sync --extra marketdata
```

启用 Qlib 可选研究适配：

```bash
uv sync --extra research
```

Alpaca 凭证通过环境变量 `ALPACA_API_KEY` 和对应 secret 配置；页面和日志不会显示 secret。
免费股票源是 IEX 研究口径，不能替换富途的实时盘口或直接比较全市场成交量阈值。

规范行情保存在 `data/market-data/` 的分区 Parquet 中，每个分区包含来源、复权口径、抓取时间、
数据版本、内容哈希和质量等级。默认读取顺序是富途、Alpaca、Yahoo；不同来源的原始记录仍会
保留用于交叉校验。详细操作和限制见 `docs/研究数据与回测V2使用说明.md`。

## 启动面板

```bash
uv run streamlit run app.py
```

浏览器打开 `http://localhost:8501`。行情权限由富途账户的行情权限决定；无对应权限时策略页
可能无法取到历史 K 线，但账户、持仓和订单仍可查看。

侧边栏“策略回测”页面可对股票/ETF运行均线交叉、RSI均值回归和20日突破回测。支持日期、
初始资金、逐标的数量、固定佣金与滑点设置，并可下载每日权益和交易记录 CSV。回测统一在
收盘生成信号、下一交易日开盘成交，以避免未来函数。

通过面板侧边栏进入独立的“交易配置”页面，可按代码精确查找，也可按代码片段或中英文
证券名称模糊搜索富途美股目录。选择结果即可添加；“当前配置”页按代码逐行设置各自的下单
股数，也可停用并删除标的。保存会写入 `.env`；已经运行的策略进程需要重启才能读取新配置。

## 安全说明

- 默认交易环境是 `SIMULATE`。实盘必须在“风控与审批 → 实盘交易控制”中完成独立配置。
- `FUTU_TRADING_ENV=REAL` 只有在 `REAL_TRADING_ENABLED=true`、`REAL_ACCOUNT_ID`、策略白名单、
  实盘额度和短时确认会话全部满足时才会放行。
- 系统不会保存富途交易密码；真实账户交易解锁必须在富途 OpenD 或富途客户端内完成。
- 只接受 `US.*` 标的。
- `.env` 已被 Git 忽略。
- 默认只计算策略信号，不会自动下单。
- 所有策略和 Gamma 页面下单都经过统一执行层：幂等去重、限额检查和 SQLite 审计。
- 主面板“一键急停”会先禁止新增仓位并撤销待成交订单；卖出平仓仍保持可用。

受控实盘配置默认关闭：

```env
FUTU_TRADING_ENV=SIMULATE
REAL_TRADING_ENABLED=false
REAL_ACCOUNT_ID=
REAL_ALLOWED_STRATEGIES=
REAL_MAX_ORDER_NOTIONAL=500
REAL_MAX_DAILY_NOTIONAL=1000
REAL_REQUIRE_MANUAL_CONFIRM=true
```

详细操作见 `docs/实盘交易控制使用说明.md`。

默认风控参数可在 `.env` 调整：`RISK_MAX_ORDER_NOTIONAL`（单笔名义金额）、
`RISK_MAX_DAILY_NOTIONAL`（当日累计名义金额）和 `RISK_MAX_PENDING_ORDERS`（待成交笔数）。
期权名义金额按 `价格 × 合约数 × 合约乘数` 计算。执行记录保存在 `data/trading.db`，可在
主面板“执行审计”查看；该数据库已被 Git 忽略。

联通验证后，把 `.env` 中 `ENABLE_PAPER_ORDERS=true`，再启动模拟策略：

```bash
uv run python scripts/run_strategies.py --strategy "SMA Cross" --loop
```

去掉 `--loop` 只运行一次。策略只会对未持有标的买入、对已持有标的卖出，数量由
配置页中与代码一一对应的数量控制；模拟盘委托使用 `TrdEnv.SIMULATE`。只有在实盘控制页完成
全部实盘闸门并把策略执行模式设为 `REAL` 时，才会使用 `TrdEnv.REAL`。

## 核心—卫星策略

该策略把 SPY/VOO/QQQ 视为核心宽基，把观察列表中的其他标的视为卫星仓。SPY 的
200 日均线决定整体风险状态；标的相对 60 日高点回撤 8%/16%/25% 时分层加仓，跌破
长期趋势或相对 200 日均线过热时减仓。股票仓位硬上限默认 70%，现有的非策略持仓也会
计入上限。卫星股必须由使用者先完成基本面审核，再加入观察列表。

只生成调仓计划时保持 `ENABLE_PAPER_ORDERS=false`：

```bash
uv run python scripts/run_strategies.py --strategy "Core Satellite"
```

确认计划后才可开启模拟下单。该策略按账户权益计算股数，不使用交易配置页的固定下单股数。
建议每天美股收盘后运行一次，不要使用分钟级循环。

可在“交易配置”页面选择保守、均衡或进取档案。三个档案统一控制股票仓位上限、Risk-On
基础仓位因子、核心权重和卫星权重，回测、主面板计划与模拟执行使用同一配置。
Core Satellite 拥有独立标的列表，可在同一页面按代码或中英文名称搜索后添加，不再与普通
策略观察列表绑定；SPY 风险基准始终由系统自动读取。

交易配置页还提供独立的“每日加速验证模式”。它只在限时验证批次中把有效频率覆盖为每日，
并使用单独的容忍带和最低交易金额，不会改写正式的周度/月度参数。同一美股交易日重复执行
只计一次；完成目标交易日数或达到安全截止时间后会自动恢复正式参数。验证订单仍归属于
`core_satellite`，但订单元数据和交易意图键会标记 `daily-validation`，便于在订单、决策和审计
证据中与正式运行区分。该模式用于加快验证调度、风控、幂等和模拟成交链路，不应把短期结果
解释为周度策略收益有效性的证明。

财报 Gamma 策略也拥有第三套独立标的列表，搜索后选择“添加到财报 Gamma”即可维护。

财报 Gamma 页面可把选定合约保存为自动策略。财报事件模式要求富途与 Nasdaq 的日期、时段
双源一致，且合约到期日覆盖财报日；任一校验失败都会阻止开仓。波动行情模式不依赖财报日，
但仍强制检查合约有效性、流动性、权利金、IV、Greeks 与组合风控。常驻模拟执行器每30秒检查
一次行情，分批建仓且只顺势加仓，并按止盈、硬止损、峰值回撤或24小时上限退出：

```bash
uv run python scripts/run_gamma_strategy.py --loop --interval 30
```

## 行情与资讯中心

左侧“行情与资讯”一级菜单集中提供三个只读工作台：

- “市场与自选行情”统一展示主要指数、所有策略自选、当前持仓、行情新鲜度、异动排序、
  标的日线趋势与动态波动状态。
- “期权市场”按标的和单个到期日显式加载期权链，展示 IV、Greeks、未平仓量、价差、
  距平值幅度和流动性评分；该评分仅用于盘口质量排序，不代表收益预测。
- “事件与公告”展示已缓存财报事件、SEC EDGAR 的 8-K/10-Q/10-K 等公司公告，以及系统
  数据源和服务事件。建议在 `.env` 设置 `SEC_USER_AGENT=你的名称 your_email@example.com`。

实时行情仍以富途为唯一交易权威；页面请求设置了短时缓存，并且不会在打开事件页时请求
期权链。SEC 公告和系统资讯只用于辅助判断，不直接触发订单。

## 统一自动交易服务

生产化运行时不再分别启动多个 `--loop`。统一服务负责交易时段判断、策略调度、订单对账、
超时撤单、进程心跳和异常告警：

```bash
uv run python scripts/run_service.py
```

`.env` 的 `SERVICE_STRATEGIES` 控制启用项，默认运行
`Core Satellite,Earnings Gamma,Volatility Long Gamma`。
基础策略如需自动交易可追加 `SMA Cross`、`RSI Mean Reversion` 或 `20 Day Breakout`。
系统监控页面展示服务心跳、策略估算盈亏、告警与全部风控参数。

统一服务使用 `exchange_calendars` 的 XNYS 正式交易日历，支持休市、提前收盘和夏令时。
订单默认先尝试中间价，并按风控中心配置的价差、滑点、追价间隔和最大次数管理未成交余量；
达到订单超时时间后自动撤单。Gamma 退出指令会提高成交优先级，但仍使用有限价保护的订单。

“自动化控制中心”是服务和策略运行设置的唯一入口，可启动、停止或重启统一服务、独立启停
波动率雷达、暂停全部策略但保留订单对账，并统一管理各策略开关和 SHADOW/PAPER 模式。
“系统监控”只负责展示心跳、任务、健康检查、告警与恢复记录，避免出现重复控制入口。
绩效使用 FIFO 成交批次计算已实现/未实现盈亏、费用、胜率、盈亏比和权益最大回撤。
健康任务每 5 分钟检查 OpenD、行情、K 线和 SQLite，每日备份数据库，轮转过大日志，并清理
超过 `DATA_RETENTION_DAYS` 的监控数据。

Gamma 自动策略保存前必须填写财报时间来源并明确确认盘前/盘后；自动加仓还会检查 IV 历史
百分位、IV/历史实现波动、预期波动以及组合 Delta、Gamma、Vega 上限，降低 IV Crush 和
Greeks 集中风险。旧的 Gamma 配置没有确认字段，将保持观察而不会自动建仓，需在页面重新保存。
波动行情模式使用独立的 IV/RV 与 IV 历史百分位上限，默认允许历史最高 IV，但不会绕过价差、
权利金、合约有效性、Greeks 和组合风险限制。所有面板时间统一显示为中国标准时间；策略内部
仍按美东交易所时钟判断交易日和开收盘。

波动行情已经拆分为独立的 `volatility_long_gamma` 策略和“波动率期权策略”页面。它拥有独立
标的、活动配置、执行模式、资金配额、审批、决策记录和 Shadow 持仓；与 `earnings_gamma`
仅共享期权链、IV/Greeks、组合风控和统一执行服务。`earnings_gamma_manual` 是页面手工提交
单批期权订单使用的兼容策略 ID，只负责这一次委托，不承担自动加仓、止盈止损或退出管理。

## Shadow 验收、策略配额与管理认证

“系统监控”可把执行模式切换为 `SHADOW`。此模式仍实时运行策略、智能定价、风控和决策日志，
但绝不调用富途下单；切回 `PAPER` 才会提交模拟订单。“运行日志”页面展示买卖/持有原因、
计算明细、操作审计、虚拟持仓和预计执行窗口，并可运行不连接富途的完整故障演练。

首次使用页面服务控制、解除急停或修改风控前，请设置管理员密码：

```bash
uv run python scripts/set_admin_password.py
```

密码只以加盐 PBKDF2-SHA256 摘要保存在 `.env`。策略资金配额和初始持仓归属在“风控中心”配置。
启用“严格执行策略持仓归属”后，每个策略只能卖出自己的虚拟份额，不能占用其他策略持仓。
建议先完成全部现有券商持仓分配并在 Shadow 模式通过故障演练，再开启严格归属和 PAPER。

## 策略上线审批、三账对账与压力测试

“上线审批”页面把每个策略的批准状态绑定到当前代码、策略参数、执行参数和风控参数指纹。
系统自动检查 Shadow 有效天数、订单数、虚拟成交率、不利滑点、服务错误和三账对账；再登记
回测、自动故障演练和风险复核后，当前版本才能在 PAPER 新增仓位；
代码或参数变化会自动让旧审批失效。审批失效不会阻止 SELL 平仓，避免风险仓位被锁死。

统一服务每分钟对比富途持仓、本地成交账本和策略虚拟持仓。发现差异会锁定该标的卖出、暂停
拥有该虚拟仓位的策略并写入告警；管理员应在“风控中心”修复初始归属，再重新对账和启用策略。
Shadow 订单会按实时买一/卖一、盘口量和参与率进行可重复的部分撮合，超时自动失效，并使用
可配置的保守股票/期权费用模型。“执行偏差”展示 Shadow 虚拟成交价、模拟成交价、成交率、
等待时间、追价次数和不利滑点。
每个订单判断还保存行情、最近 K 线、账户、相关持仓、参数和代码指纹，支持事后复现。
压力测试覆盖正股下跌 10%–30%、IV Crush 30%–70%、期权归零及流动性恶化场景。

统一服务每天自动抓取 Nasdaq 财报日历，缓存配置标的的日期与盘前/盘后信息，并同步已有
Gamma 活动；方向和具体期权合约仍必须人工选择。管理员登录带会话超时和连续失败锁定，告警
Webhook 可通过 `ALERT_WEBHOOK_SECRET` 添加 HMAC-SHA256 签名。

macOS 自动恢复模板位于 `deploy/com.futu.paperquant.plist.example`。确认路径后复制到
`~/Library/LaunchAgents/com.futu.paperquant.plist` 并使用 `launchctl bootstrap` 注册；模板设置了
`KeepAlive`，进程异常退出后会自动重启。不要同时手动启动统一服务，单实例锁会拒绝第二个进程。

## 事件驱动执行与持续验证

统一服务使用富途模拟盘订单/成交推送实时更新本地账本，定时订单查询仅作为断线兜底。启动或
恢复连接后会先同步订单、运行三账对账，再允许新增风险。监控页“恢复与日报”记录进程启停、
恢复结果、推送事件和每日运行摘要。

财报日历采用富途主源与 Nasdaq 备用源交叉核验；日期和盘前/盘后一致才允许标记为已确认，
单一来源或来源冲突不会触发 Gamma 自动开仓。Shadow 撮合考虑限价穿透、买卖价差、盘口量、
常规/扩展时段流动性、期权未平仓量和确定性排队概率。

组合风控把正股与期权折算为 Delta 金额，并限制净 Delta、同一正股家族、高相关标的组合及
Gamma/Vega/Theta。每日相关性矩阵由近 90 根日线更新。回测页支持 Walk-forward 分窗验证、
Bootstrap 正收益概率和滑点敏感性，并可直接写入上线审批证据。

风控中心可根据模拟订单的名义金额、每日交易量、决策时买卖价差和实际滑点生成校准建议；
系统永远不会自动应用建议，必须由管理员逐条批准。

## 基础设施与灾备

“基础设施与灾备”页面提供数据库迁移状态、Parquet 数据血缘、恢复点与隔离恢复演练、配置发布审批、权限矩阵、密钥状态和存储容量监控。统一交易服务会定时执行历史归档、恢复点创建、灾备演练及容量检查。

PostgreSQL 迁移采用显式离线流程，默认运行数据源仍是 SQLite。先执行安全检查：

```bash
uv run python scripts/migrate_to_postgres.py --dry-run
```

确认目标库为空且已完成外部备份后，才使用 `--execute`。容器部署模板见 `docker-compose.yml` 和 `.env.docker.example`；自动交易相关容器位于 `paper-automation` profile，且仍只允许富途模拟盘。

## 稳定性运营

“稳定性运营中心”提供全页面兼容巡检、隔离端到端模拟验收、24 小时运行指标、中文事件与安全恢复、订单幂等审计、动态资金建议、策略模拟验收和每日运营报告。

静态检查全部页面：

```bash
uv run python scripts/check_streamlit_pages.py
```

OpenD 在线时可逐页真实渲染：

```bash
uv run python scripts/check_streamlit_pages.py --runtime
```

真实渲染只读取富途模拟账户；OpenD 不可连接时会快速停止。动态资金功能默认只生成保守建议，必须管理员确认才会修改模拟盘策略预算。

## 长期模拟验证

“长期验证”页面展示账户和策略的 7/30/90 天指标、FIFO 已实现收益、手续费与滑点、按时段分层的执行质量、稳定性评分、组合 Greeks、候选评分和容量校准。后台每天执行一次长期验证。

自动治理只能将发生显著走样的策略从 `PAPER` 降为 `SHADOW`，永远不会自动升级。恢复到 `PAPER` 必须由管理员在页面选择策略并填写人工复核原因。样本不足始终显示为不足，不会自动放宽验收条件。
