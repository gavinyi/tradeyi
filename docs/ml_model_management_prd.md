## 一、背景与问题

### 1. 现状：ML 能力三层全断
| 层 | 事实 | 证据 |
| :--- | :--- | :--- |
| **调度** | Windows 计划任务 `TradeFuto-ML-Monthly-Retrain` **已丢失**，无任何触发器 | `schtasks` 查不到（ERROR: cannot find） |
| **依赖** | `scikit-learn` **从未安装**（`pyproject.toml` 有 `[ml] extra`） | 10-01 那次执行失败于「scikit-learn 未安装」 |
| **可见性** | 模型打分失败时 **`logger.info` + 静默回退规则打分**，无异常、无告警、INFO 级 | `ml_scorer.py:54-62` |

### 2. 后果
- 生产模型 `volatility_scorer_v3.pkl` 停在 **2026-09-09（44 天）**；
- **ML 打分已静默降级为规则打分约 6 周**，从外面看 `scorer.enabled` 恒为 `True`（「ML 是启用的」）；
- 模型**年龄不可信**：`volatility_scorer_v3.json` 的 `trained_at: 2026-10-14` 是**元数据刷新时间**（那个已删除的假重训脚本写的，P1-05 已清理），**不是训练时间**——读它做守卫会永远显示「9 天」、永远绿。

### 3. 产品目标
**把 ML 从「黑盒依赖」变成「可观测、可配置、可对照的策略组件」**：
1. **可见**：模型新鲜度、打分方式（ML / 规则降级）、重训历史，全部上页面；
2. **可配**：打分方式、AUC 门控、样本门槛、特征集、频率，全部可配；
3. **可对照**：实盘跑 ML、模拟盘跑规则（或反之），**直接量出 ML 的增量**。

## 三、页面信息架构（四区块）

### 区块 ① 模型状态卡（一眼看清）
| 字段 | 说明 |
| :--- | :--- |
| 当前生产模型 | 版本、**训练时间**（取自 pkl 内 `trained_at`，回落 mtime）、**年龄（天）** |
| 新鲜度指示 | 🟢 **<30 天** / 🟠 **30–34 天**（建议重训）/ 🔴 **≥35 天**（必须重训）——**与 §四 状态表同一套阈值** |
| 当前 AUC | 已知时显示，未知时显示「基线未知」 |
| **当前打分方式** | **`ML 打分`** / ⚠️ **`规则降级`** |
| 降级原因 | 缺依赖 / 加载失败 / 模型不兼容 / **特征不匹配** / 其他（**五种，见 §四**） |
| 生效租户 | 哪些租户在用 ML、哪些在用规则 |

> **同一页面不得出现两套阈值**：状态卡的指示必须与 §四 状态表逐字一致（30 / 35 两档）。

### 区块 ② 重训控制
- **手动触发重训**（管理员权限 + **二次确认**）
- **重训历史表**（独立列显示原因）：

| 时间 | 租户 | 触发 | 新 AUC | 旧 AUC | 结果 | **原因** | 样本 | 耗时 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| 2026-10-24 02:00 | futu_real_master | 月度 | 0.71 | 0.70 | **REPLACED** | — | 342 | 182s |
| 2026-09-24 02:00 | futu_real_master | 月度 | — | 0.70 | **SKIP** | `AUC_UNKNOWN` | — | — |
| 2026-09-17 02:00 | futu_real_master | 手动 | 0.68 | 0.70 | **SKIP** | `AUC_NOT_IMPROVED` | 318 | 161s |
| 2026-09-10 02:00 | futu_real_master | 月度 | — | — | **FAILED** | `TRAIN_ERROR` | — | — |

- **AUC 门控可视化**：新 AUC vs 绝对下限（0.55）vs 旧 AUC + 最小边际（0.01），**一眼看出为什么没替换**

### 区块 ③ 配置区（可配置因子，**9 项**，与设计 §2.1 同数同名）
| 因子 | 说明 | 默认 | 生效租户 |
| :--- | :--- | :--- | :--- |
| **打分方式** | `ML 打分` / `规则打分` | ML | 逐租户 |
| **评分阈值 `ml_threshold`** | ML 分数低于该值不入选 | 现有值 | 逐租户 |
| **AUC 绝对下限** | 低于则不替换 | 0.55 | 逐租户 |
| **最小改进边际** | 门控「**相对改进**」的组成部分：须优于旧 AUC 至少该值 | 0.01 | 逐租户 |
| **最小样本数** | 不足则 SKIP | 现有值 | 逐租户 |
| **训练窗口** | 用最近 N 天数据 | 现有值 | 逐租户 |
| **特征集开关** | 逐特征启用/禁用 | 全开 | 逐租户 |
| **模型路径 `model_path`** | **按租户覆盖**模型文件位置（缺省用全局路径） | 全局路径 | 逐租户 |
| **生效租户** | 实盘 / 模拟 / 两者 | 两者 | — |

> **「重训频率」不在此表**——它属于**调度配置**（`run_service` 的 interval / due 判据），**不是租户打分配置**。混进来会让「调度节奏」和「打分行为」两个概念纠缠（采纳 Architect 补充）。

**每次保存显示最近 5 条变更**（谁 / 何时 / 为什么 / 改了什么）。

### 区块 ④ 对照视图
> ## ⛔ 本期不含对照视图 —— 单列 **P1-F**
>
> **本区块不在本期（P1-A/B/D/E）范围内**，原因：对照视图需要分数数据源，而 **`decision_logs` 目前无 `tenant_id` 列**——**必须先完成 `decision_logs` 租户化**，否则实盘与模拟的分数混在一起，**对照失去意义**。
>
> **P1-F（单列一期）**：`decision_logs` 加 `tenant_id` + 回填 + 索引 → 对照视图上线。
> **动的是决策主链，值得单独一批、单独验证，不与 ML 恢复挤在一起**（Chief 裁定，2026-10-23）。

**P1-F 内容（预留，本期不实施）**：
- 实盘（ML）vs 模拟（规则）的**候选评分分布**、**入选标的差异**
- 直接回答「**ML 到底有没有用**」
- **前置依赖**：`decision_logs` 租户化 **必须先于** 对照视图上线（两者同一批次）

## 四、状态语义（五种，必须可区分）

| 状态 | 判据 | 展示 | 告警 |
| :--- | :--- | :--- | :--- |
| 🟢 **正常** | ML 打分生效 且 模型年龄 < 30 天 | 「ML 打分 · 模型 12 天」 | — |
| 🟠 **过期（建议重训）** | ML 打分生效 且 年龄 **≥30 天** | 「ML 打分 · ⚠️ 模型 32 天 · 建议重训」 | WARN |
| 🔴 **严重过期（必须重训）** | ML 打分生效 且 年龄 **≥35 天** | 「ML 打分 · 🔴 模型 44 天 · 必须重训」 | **ERROR** |
| 🔴 **降级** | 回退到规则打分 | 「⚠️ **规则降级** · 原因：<原因>」 | **ERROR**（必须让人看见） |
| 🛑 **连续 SKIP** | 连续 ≥2 次重训 SKIP | 「重训连续未生效 · 原因：<原因>」 | ERROR |

**阈值口径（两档，与架构设计一致）**：
- **≥30 天 → 🟠 WARN**「建议重训」——提示性，不扰民；
- **≥35 天 → 🔴 ERROR**「必须重训」——事故级，必须让人知道。

**理由**：一刀切 ERROR 会**训练用户忽略告警**——**告警疲劳比没有告警更糟**。两档给「该关注」与「必须处理」留出区分。

**降级原因（五种，必须全）**：`缺依赖` / `加载失败` / `模型不兼容` / **`特征不匹配`** / `其他`。
**「特征不匹配」是真实失效模式**——特征 schema 漂移会让加载「成功」但打分无意义（采纳 Architect 补充）。

**关键原则**：**降级不拦单是对的，但必须让人一眼看见**——「静默降级 6 周」是本次最贵的教训。

## 五、文案规范

| 场景 | 文案 |
| :--- | :--- |
| 正常 | `ML 打分生效 · 模型 12 天 · AUC 0.71` |
| 过期（建议重训） | `ML 打分生效 · ⚠️ 模型 32 天 · 建议重训` |
| 严重过期（必须重训） | `ML 打分生效 · 🔴 模型 44 天 · 必须重训` |
| 降级 | `⚠️ 规则降级 · 原因：scikit-learn 未安装 · ML 打分不可用` |
| 连续 SKIP | `🛑 重训连续 3 次未生效 · 原因：AUC 未改进 · 模型未更新` |
| 基线未知 | `AUC 基线未知 · 不允许在无基线情况下替换模型` |

**文案里的天数必须与状态级别一致**：30–34 天用「建议重训」（WARN），**≥35 天必须用「必须重训」（ERROR）**——**文案与状态级别不一致，比没有文案更糟**（用户会按文案判断轻重）。

**禁止**：只写「重训失败」而不写原因；只写「模型过期」而不写天数。

## 六、空态与异常态

| 情形 | 展示 |
| :--- | :--- |
| 无重训历史 | 「暂无重训记录」+ 手动触发入口 |

## 七、可配置因子（汇总，**9 项**，与设计 §2.1 同数同名）
见区块 ③：`打分方式` / `评分阈值 ml_threshold` / `AUC 绝对下限` / **`最小改进边际`** / `最小样本数` / `训练窗口` / `特征集开关` / **`模型路径 model_path`** / `生效租户`，**以及门控三要素的组合**（绝对下限 ∧ 相对改进 ∧ 最小边际）。

**全部按租户可配**，走与 P0-7 同构的三层解析链（`real_account_config:{id}` 的 `ml` 段 → `ml_scoring:{tenant}` → env 兜底）；**部分配置即拒绝**、**回落必须可观测**、**解析失败抛异常**。

**「重训频率」属调度配置，不在此列。**

## 八、验收（5 条，可演示）

1. **状态可见**：构造「sklearn 缺失」→ 页面显示 🔴 **规则降级** + 原因 + ERROR 告警 + 心跳；`scorer.enabled = False`。
2. **新鲜度准确**：构造 pkl `trained_at` 为 **N 天前**（N 相对生成，**不写死天数**）、且 json `trained_at` 为**更近**的日期 → 页面**必须显示更老的那个**（即 pkl 的天数）。
   **关键判据**：**json 与 pkl 不一致时，必须显示更老那个**——这条直接证明守卫**不读 json 的 `trained_at`**（那是元数据刷新时间，是陷阱）。
3. **门控正确**：新 AUC 0.56（>0.55）但旧 AUC 0.70 → **SKIP + 原因 `AUC_NOT_IMPROVED`**；新 AUC 0.52 → **SKIP + `AUC_BELOW_FLOOR`**；旧 AUC 未知 → **SKIP + `AUC_UNKNOWN` + 告警**。
4. **连续 SKIP 告警**：连续 2 次 SKIP → 触发「重训连续未生效」ERROR。
5. **配置留痕**：改 AUC 下限 → 页面显示「谁 / 何时 / 为什么 / 改了什么」，**最近 5 条可查**。
