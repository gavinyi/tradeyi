# 期权退出策略拆分设计

## 目标

财报 Gamma 与波动率期权继续共享行情、持仓读取、风控、下单、撤单和对账，但不再共享策略退出决策。波动率策略必须从真实持仓周期独立计算止盈、止损、峰值回撤、最长持有、波动收缩、IV 衰减、Gamma/Theta 效率衰减和到期风险。

## 边界

- `decide_earnings_action` 只处理财报事件窗口、事件后监控和财报后最长持有。
- `decide_volatility_action` 只处理动态波动持仓，不接受财报事件时间。
- `run_campaign` 保留为共享编排器，但根据 `strategy_id/trigger_mode` 分派不同策略决策器。
- 波动率周期状态按 `volatility_long_gamma:<code>` 保存，持仓从 0 变为正数时初始化周期；平仓或新周期开始时清理历史峰值和确认计数。
- 实际持仓成本作为峰值基线。入场 IV 和 Gamma/Theta 效率在首次观察到已成交持仓时记录，不继续使用候选生成时的陈旧快照。

## 波动率退出优先级

1. 硬止损，持仓期间始终生效。
2. 到期日临近收盘强制退出。
3. 止盈，持仓期间始终生效。
4. 峰值回撤，仅在仓位曾经盈利后生效。
5. 最长持有时间，从本轮持仓建立时间计算。
6. 实现波动收缩、IV 衰减、Gamma/Theta 效率衰减，达到最短持有时间且连续确认后退出。
7. 其他情况继续持有；只有动态信号仍有效且现有仓位盈利时才允许金字塔加仓。

## 独立参数

波动率页面提供最长持有小时、最短持有分钟、IV 衰减阈值、Gamma/Theta 效率衰减阈值和收缩确认次数。自动雷达生成活动时写入同一套默认值。财报策略参数和页面不受影响。

## 验收

- 波动率止盈和峰值回撤不再等待入场窗口结束。
- 波动率最长持有原因不出现“财报后”。
- 新持仓周期不会继承上一周期最高价。
- 财报策略原有事件窗口行为保持不变。
- 配置页面、自动雷达和执行服务写入/读取同一组波动率退出参数。
- Ruff、专项测试、全量测试和 Streamlit 页面检查通过。
