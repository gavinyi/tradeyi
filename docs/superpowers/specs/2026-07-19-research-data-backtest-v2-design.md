# 研究数据与回测 V2 设计

## 目标

在不替换现有富途模拟交易链的前提下，建设统一多源研究数据层、可审计的回测 V2、可选 Qlib 研究适配，以及更可信的期权历史证据。系统在没有任何第三方 API key 或 Qlib 依赖时仍须完整启动和交易。

## 已确认的约束

- 富途 `TrdEnv.SIMULATE` 是账户、订单、成交和实时交易行情的唯一真相源。
- 第三方免费数据只用于历史补全、交叉校验和研究，不直接决定实时委托价格。
- 所有时间内部保存为 UTC，界面统一显示中国时区。
- 第三方凭证只从环境变量读取，不能写入数据库、日志或浏览器数据。
- Qlib 是可选研究适配，不能成为 Streamlit、统一交易服务或雷达服务的启动依赖。
- 数据不足、来源冲突或报价不可成交时必须明确降级或拒绝，不能用中间价伪造可成交结果。
- 现有策略审批、风控、统一交易服务和模拟盘限制保持不变。

## 方案选择

### 方案 A：直接以 Qlib 替换现有回测与数据层

优点是因子和实验能力现成；缺点是侵入交易系统、期权适配差、依赖重，且 Qlib 数据本身不能解决美股期权历史盘口问题。不采用。

### 方案 B：只在现有回测中增加几个指标

改动小，但无法解决富途配额、数据来源、复权、时间可见性和实验复现问题。不采用。

### 方案 C：统一数据层 + 现有回测 V2 + 可选 Qlib 适配

在现有系统外围增加清晰边界，股票研究和期权事件回放分别演进，最终统一进入当前风控与交易链。采用此方案。

## 架构

### 统一数据层

定义 `MarketDataProvider`：

- `get_bars(symbol, start, end, interval)` 获取标准 OHLCV。
- `get_corporate_actions(symbol, start, end)` 获取拆股和分红。
- `health()` 返回来源可用性和限制说明。

首批 Provider：

- `FutuMarketDataProvider`：主历史源，包装现有 Broker K 线能力。
- `AlpacaMarketDataProvider`：可选历史补全，需要 `ALPACA_API_KEY` 和 `ALPACA_API_SECRET`。
- `YahooMarketDataProvider`：可选三级研究备用，依赖 `yfinance` 可选包。

标准数据列包括 `symbol`、`timestamp`、`session_date`、OHLCV、`adjustment`、`source`、`feed`、`fetched_at`、`available_at`、`quality_status` 和 `dataset_version`。

`CanonicalMarketDataStore` 使用分区 Parquet 保存规范数据，并保存 manifest。读取时只合并同一复权口径；来源冲突超过阈值的数据进入隔离结果，不静默覆盖。

`MarketDataRouter` 按富途、Alpaca、Yahoo 的顺序补缺口。单个来源故障只影响对应请求，不影响应用启动。

### 回测 V2

保持现有 `BacktestResult` 向后兼容，扩展指标：

- CAGR、年化波动率、Sharpe、Sortino、Calmar。
- 最大回撤和回撤持续交易日。
- 胜率、盈亏比、Profit Factor、每笔期望值。
- 换手率、平均和最大资金暴露。
- 基准总收益、超额收益、Alpha、Beta、上行和下行捕获率。

成交模型继续执行 T 日收盘信号、T+1 开盘成交，并支持固定手续费、滑点、成交量参与率、部分成交和不可成交记录。没有 volume 时保持原有行为并记录降级原因。

滚动验证升级为按时间顺序的训练、验证、测试窗口；事件策略提供 purge/embargo 间隔。压力测试至少覆盖 1、1.5、2 倍滑点及 Bootstrap。验收证据记录数据版本、参数、基准和窗口。

### Qlib 研究适配

`QlibResearchAdapter` 提供：

- 检测 `pyqlib` 是否安装。
- 从规范日线导出 Qlib 可读取的数据集目录或标准研究 DataFrame。
- 将预测结果标准化为 `research_signal`，包含模型、版本、生成时间和数据版本。

Qlib 通过 `research` 可选依赖安装。未安装时中文界面显示“未启用”，其余功能不受影响。Qlib 信号不能直接下单，只能登记为实验产物并进入现有策略验证和风控链。

### 期权历史增强

扩展现有快照覆盖诊断：

- 每份回测证据记录数据起止时间、有效交易日、报价新鲜度、价差、缺失率和来源。
- 对不足样本返回结构化 `INSUFFICIENT_EVIDENCE`，说明缺少天数、样本数或可成交盘口。
- 增加按 Delta、DTE、Call/Put、价差和流动性分桶的研究汇总。
- 组合重放按净权利金、合约乘数、手续费和腿级 bid/ask 计算，不使用不可成交的中间价。

## 界面

在“研究与系统”下增加“数据研究中心”，采用延迟加载：

- 数据源状态：富途、Alpaca、Yahoo、Qlib 是否配置与可用。
- 数据目录：数据集、来源、范围、行数、版本、质量等级。
- 数据质量：缺口、重复、异常价格、来源冲突和隔离原因。
- 回测 V2：中文指标、基准对比、滚动窗口和压力测试。

昂贵请求必须由表单提交或显式按钮触发，并使用有界 TTL 缓存；隐藏页签不能自动抓取行情。

## 错误处理与安全

- Provider 返回统一异常类型：未配置、限频、网络故障、响应无效、无数据。
- Router 保留每次尝试结果，成功降级时展示实际来源。
- 网络调用设置超时、有限重试和指数退避；不绕过数据提供商限制。
- API key 在日志中统一脱敏。
- 实时下单代码不得导入 Alpaca/Yahoo Provider。
- 新测试必须验证 Broker 仍强制 `TrdEnv.SIMULATE`。

## 测试与验收

- Provider 契约、规范化、去重、来源优先级和冲突隔离单元测试。
- 回测指标使用可手算权益曲线验证。
- 时间可见性、T+1、部分成交、基准对齐和无成交量降级测试。
- Walk-forward 时间边界和 embargo 测试。
- Qlib 未安装/已安装适配测试，不要求 CI 安装 Qlib。
- 期权证据不足和可成交盘口测试。
- Streamlit 页面静态编译、运行时 smoke test、全量 pytest 和 Ruff。

## 非目标

- 不增加实盘交易能力。
- 不承诺免费获得完整 OPRA 历史数据。
- 不用第三方实时行情替代富途下单价格。
- 首轮不训练深度学习模型、不建设分布式数据服务。
