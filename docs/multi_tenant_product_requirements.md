# 通用多租户量化架构（Multi-Tenant Architecture / N-Tenant）产品需求规格说明书 (PRD)
> **文档版本**: 2.0 (Institutional Multi-Tenant Edition)  
> **负责人**: Product (产品经理)  
> **生效日期**: 2026-10-20  
> **适用范围**: Tradeyi 量化交易系统 (美股股票 + 期权高弹性多资金池运行底座)

---

## 一、 业务背景与演进动因

### 1. 业务现状复盘与核心矛盾
当前系统的执行层在切换至实盘后，模拟盘以“伴生通道（Companion）”的形式挂载在实盘循环中。在 2026-10-20 的 `US.QQQ261029C735000` 期权交易中暴露出关键缺陷：
1. **状态机断层（孤儿单）**：实盘平仓毫秒级成交，伴生模拟单超时撤单后缺乏后续重挂与追单状态机，导致模拟持仓掉队滞留；
2. **伴生从属违背量化规律**：模拟盘是前向实战推演（Forward-Testing）、标的赛马孵化、模型参数验证的生命线，具备独立的交易生命周期；
3. **二元硬编码瓶颈**：业务未来规划接入多个真实交易专户（如主专户、机构备用专户、不同券商专户）、多套不同风险偏好的前向演练沙盒（高频期权沙盒、大资金现货底仓沙盒）。系统若仅停留于“实盘 + 模拟”的二元写死设计，将彻底堵死后续资金池横向扩容（Scale Out）的可能。

### 2. 产品定位与目标
全面对标全球顶尖机构级量化系统（**Bloomberg AIM / PORT、Charles River IMS、IBKR Institutional & Advisor 多账户体系、QuantConnect Lean 资金池管理**），构建 **通用多租户量化架构（N-Tenant Architecture）**：
- **租户实体平权化（First-Class Tenants）**：所有注册账户不论是真金专户还是沙盒专户，均享有对等的订单生命周期管理、超时重挂追单、动态止盈止损及三账对账守护；
- **故障域绝对物理解耦**：各租户在底层连接、操作系统守护进程、数据库账本与风控边界上彻底隔离，任何沙盒的高频实验或网络波动绝不影响实盘真金；
- **配置驱动即插即用（N-Account Scale Out）**：支持通过租户注册表动态添加第 3、第 4 直至第 N 个实盘或模拟账户，业务零改动即可实现多资金池并发运作。

## 二、 工业级架构对标与原则

| 维度 | 传统单轨/伴生模式（已废弃） | 硬编码双轨模式（过渡态） | 通用多租户架构 N-Tenant（本 PRD 标准） |
| :--- | :--- | :--- | :--- |
| **账户模型** | 实盘为主，模拟盘为临时调用 | 仅硬编码 REAL 与 PAPER 两个环境 | **实体抽象 `TenantProfile`，动态支持 N 个独立账户** |
| **生命周期** | 模拟撤单后无后续状态机 | 仅针对两个固定进程编写调度 | **每个租户独占完整的执行器与状态机闭环（追单/撤改/止损）** |
| **数据契约** | 存在跨环境混查接口 | 以 `(account_id, env)` 二元组合区分 | **所有核心账本与意图强绑定 `tenant_id` 命名空间硬分区** |
| **系统进程** | 单进程混合跑，相互争用 | 固定两个死进程 (`real`/`paper`) | **参数化守护引擎 `run_service.py --tenant <tenant_id>`** |
| **风控层级** | 门禁规则易产生穿透或误伤 | 粗粒度按 REAL/PAPER 切分 | **租户绑定独立 `RiskProfile`，凡真金账户强挂载绝对门禁** |
| **界面交互** | 账目混杂，容易产生认知混淆 | 简单双选切换 | **动态多租户驾驶舱（全景看板 + 租户视窗精准切片）** |

## 三、 详细业务需求规格

### 1. 租户实体模型（Tenant Profile Registry）
系统建立全局统一的租户元数据注册中心（支持数据库与配置注入）：
- **`tenant_id`**：全局唯一租户标识（例如 `futu_real_master`、`futu_paper_sandbox`、`futu_real_sub01`、`ibkr_real_hedge`、`alpaca_crypto`）；
- **`broker_type`**：底层接入券商类型（`FUTU`、`IBKR`、`ALPACA` 等）；
- **`trading_env`**：环境类型，`REAL`（真实真金）或 `SIMULATE`（沙盒模拟）；
- **`account_id`**：底层实际分配的资金账号；
- **`risk_profile`**：绑定的独立风控规则。
  - **不可逾越的红线（Product Redlines）**：凡 `trading_env == 'REAL'` 的租户，必须强制挂载实盘交易确认码、单笔/日累计名义限额、审批指纹、以及 `submit_limit` 唯一通道，绝不允许以“多租户灵活性”为由弱化或旁路；
- **`strategy_whitelist`**：该租户授权调度的策略集。

### 2. 执行与全生命周期自闭环（Tenant-Level Execution Lifecycle）
每一个激活的租户实例必须拥有独立、完整的执行生命周期闭环：
1. **订单追价与重挂（Smart Reprice）**：
   - 限价单在 `ORDER_TIMEOUT_SECONDS` 内未完全成交时，执行器自动撤单，并依据当前租户的最新买卖档口与限价范围自动重算补挂新单；彻底消灭无人照看的“孤儿单”；
2. **期权到期处置（Option Disposition Safeguard）**：
   - 所有在仓期权持仓在到期日（DTE <= 0）临近收盘前 60 分钟，若处于实值（ITM），均自动触发平仓或保护性处置，杜绝期权归零或违约；
3. **独立对账闭环（Independent Three-Way Reconciliation）**：
   - 每 30 秒独立执行当前租户的「券商底层仓位 ↔ 本地成交记录 ↔ 租户虚拟账本」核算；任何单一租户发生账目不平，仅阻断该租户的异常标的，严禁跨租户扩散。

### 3. 数据契约与存储分区（Data & Ledger Isolation）
1. **显式列与联合约束硬分区**：
   - `virtual_positions`、`reconciliation_adjustments`、`risk_limits` 等核心表均增加显式 `tenant_id` 字段（并关联 `account_id` 与 `env`）；
   - 彻底废除不带租户标识的全局模糊查询方法；
2. **意图幂等性保护（安全审查修正）**：
   - 为规避字符串重构引入的重复报单真金风险，**现有 `intent_key` 格式保持不动**，通过新增显式列 `tenant_id`、`account_id`、`env` 与数据库联合唯一约束保障跨租户强隔离；
3. **配置键租户命名空间隔离**：
   - `execution_mode`、`strategy_execution_mode`、策略暂停标志及急停开关，均强制格式化为 `<key>:<tenant_id>`（如 `kill_switch:futu_real_master`），从根源杜绝不同租户运行同名策略时的参数互相污染。

### 4. 前端交互：多租户全景驾驶舱（Multi-Tenant UI）
在 Streamlit 统一监控终端中：
1. **全局租户视窗选择器（Tenant Viewport Selector）**：
   - 页面顶部常驻动态下拉选择器，选项动态读取自 `tenants` 注册表，清晰带有视觉角标（如 `🟢 [实盘] 富途主专户 (..9109)`、`🟡 [模拟] 波动率沙盒 (..0229)`、`🔵 [实盘] 机构子专户B (..8821)`）；
   - 切换后，资产卡片、持仓列表、活动订单、生命周期流水与对账状态全部自动联动刷新为该租户切片；
2. **多资金池全景矩阵（Multi-Account Portfolio Matrix）**：
   - 资产概览页提供一览表，横向汇总所有实盘真金资产与沙盒前向推演收益，方便掌控全局资金盘子。

## 四、 实施路线图（Milestones）

```text
[阶段一: 数据契约强隔离与租户抽象] (P0)
 ├── 抽象 TenantProfile 元数据模型，定义 tenants 注册表规范
 ├── 核心 Store 读写接口全面参数化并要求 tenant_id 必填
 ├── 数据库表新增 tenant 显式字段与联合约束 (现有 intent_key 格式保持不动)
 ├── 配置键全面租户命名空间前缀化 (<key>:<tenant_id>)
 └── 编写可注入的跨租户强隔离单元测试套件，通过全量回归
      ▼
[阶段二: 守护进程参数化与状态机对等] (P0)
 ├── run_service.py 升级为支持 --tenant <tenant_id> 参数化拉起
 ├── 进程 PID、单例锁与对账循环全面解耦为独立 Worker
 ├── 模拟沙盒获得平等的订单超时撤改与自动重挂闭环
 └── 孤儿持仓侦测雷达 (Orphan Watchdog) 落地常态化守护
      ▼
[阶段三: 前端多租户动态驾驶舱] (P1)
 ├── Streamlit 顶部上线动态租户切换器 (自动联动 41 个页面)
 ├── 核心监控看板支持租户数据精准切片与全景聚合
 └── 生产部署：实盘零停机拉起多租户独立守护进程
```
