# 行情数据源与期权盘口容错方案

更新时间：2026-07-25

## 结论

自动下单时，期权实时盘口仍以富途 OpenD 为主数据源。免费的第三方 API 可以补充股票行情、历史 K 线、研究数据和回测数据，但不建议替代富途作为期权自动交易的实时 bid/ask 来源。

原因很简单：美股期权实时盘口来自 OPRA，完整实时数据通常需要交易所授权或券商账户权限。真正“免费、实时、全市场、可商用下单”的美股期权盘口基本不存在。

## 当前系统已采用的容错方案

### 1. 下单前强制刷新

策略执行前会重新读取：

- 目标期权合约快照
- 对应正股快照

如果第一次失败或数据不合格，会短等待后重试。

### 2. 开仓严格、平仓韧性

开仓：

- 期权行情必须新鲜；
- 正股行情必须新鲜；
- 期权必须有可用双边盘口；
- 买一、卖一不能倒挂；
- 价差不能超过策略阈值。

平仓：

- 如果已有持仓，但期权行情过期或盘口不可用，不会悄悄跳过；
- 系统会记录为 `WAITING_EXIT_LIQUIDITY`；
- 下一轮服务循环继续刷新并尝试退出。

### 3. 可复盘事件

行情或盘口造成的阻塞会写入审计事件：

- `OPTION_MARKET_DATA_BLOCKED`：无持仓开仓前被阻断；
- `OPTION_MARKET_DATA_WAITING`：已有持仓，等待可退出盘口；
- `OPTION_EXIT_WAITING_FOR_BID`：卖出时买一价不可用，等待下一轮退出；
- `OPTION_QUOTE_DEGRADED_ACCEPTED`：行情轻微延迟但盘口可用，降级通过。

这些事件后续会体现在运行日志、交易诊断和策略复盘中。

## 第三方免费 API 的定位

### 适合使用

- 股票日线/分钟线补全；
- 回测数据补全；
- 市场宽度、指数、板块研究；
- 期权链结构参考；
- 非交易决策前的研究辅助。

### 不适合使用

- 直接替代富途的期权实时 bid/ask；
- 自动下单价格；
- 止损/止盈的最终执行价格；
- 高频刷新全市场期权链。

## 可考虑的数据源

| 数据源 | 免费层适用场景 | 主要限制 |
| --- | --- | --- |
| Alpaca | 股票 IEX 行情、历史数据、研究补全 | 免费股票口径不是全市场 SIP；期权实时 OPRA 权限通常受限 |
| Tradier | 有券商账户时可取股票/期权报价 | 权限和实时性依赖账户与数据协议 |
| Polygon | 股票/期权历史与实时数据能力较强 | 高质量实时期权通常不是免费层 |
| Finnhub | 股票基础行情、部分公司数据 | 期权实时盘口覆盖和授权有限 |
| Yahoo Finance / yfinance | 历史研究、人工检查 | 非正式交易数据源，实时性和稳定性不可作为下单依据 |

## 最佳实践

1. 自动交易价格以券商实时盘口为准。
2. 免费 API 只作为研究和回测补充。
3. 期权开仓宁可少交易，也不要用过期/无盘口数据交易。
4. 期权平仓不能因为盘口短暂不可用就丢状态，应进入等待退出队列。
5. 复盘时重点统计：
   - 因行情过期错过多少次；
   - 因盘口不可用等待多久；
   - 最后是否成功退出；
   - 等待期间盈亏是否恶化。
