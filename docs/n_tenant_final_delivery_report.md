## 一、 项目背景与演进目标

在量化交易系统日常实盘运行中，实盘真金交易（REAL）与前向推演模拟盘（SIMULATE）长期存在数据耦合、进程资源竞争、状态机不对等等痛点。为满足用户提出的“支持未来接入更多租户/账户（通用多租户模型 N-Tenant）、实盘与模拟对等独立并行、物理隔离、三账分区与 UI 隔离，演进对运行中实盘零停机零干扰”的战略要求，团队启动了本次重大架构演进与安全加固。

## 三、 关键安全缺陷与专项加固记录

### 1. P0 缺陷：租户急停「假刹车」安全漏洞（已彻底闭环）
- **现象定位**：Reviewer 在阶段三审查中抓出关键链路断点——风控中心按租户点一键急停时，UI 写入 `kill_switch:{tenant_id}`，但底层风控引擎（`risk.py:100`）只读取 `kill_switch:{account_id}` 与全局键，导致生产下单路径看不见急停开关，真金刹车静默失效。
- **修复方案**：`store.set_kill_switch` 升级为严格双写机制，同时写入 tenant 键与 account 键，读路径零改动。
- **端到端验收**：Reviewer 在临时库上实测四条断言全过（BUY 闸门即刻感知拦单、SELL 通畅、无关账户不误伤、解除同步清零）；Tester 补充防回归用例（`test_tenant_kill_switch_blocks_risk_engine_buy`），15/15 全绿。

### 2. P0.5 缺陷：复盘任务反复重试 27 轮与 KeyError 根除（已彻底闭环）
- **现象定位**：今早 05:15 定时复盘任务迟迟未生成 Markdown 与 IM 推送，累计退避重试达 27 轮。
- **根因分析**：`strategy_review.py` 在生成表格排序时裸调用 `sort_values(['优先级排序', ...])`，因该列在部分数据源中缺失导致抛出 `KeyError: '优先级排序'`，异常中断后未能写入当日完成标记。
- **修复与验收**：增加派生与 9 兜底逻辑，Tester 补充 None 字段与双瘦表变体用例（4/4 PASS）；今早 08:18 该任务已成功完成，报告落盘并在数据库中更新为 `DELIVERED` 成功推送微信/IM。

### 3. P0.5 运维排查：`service.log` 停写假象定性与行缓冲加固（已彻底闭环）
- **真相澄清**：美股于北京时间 04:00 收盘后策略扫描正常停止，盘后后台运维任务只写 SQLite 不打控制台输出，03:58 停写纯属正常静默，主调度循环始终每 10 秒正常执行。
- **加固落地**：在 `run_service.py` 显式开启行缓冲，在 `start.bat` 注入 `-u` 强制无缓冲标准输出，彻底解决 Windows 下重定向缓冲带来的观察延迟。

### 4. P1 缺陷：期权止损通道加固（QQQ 病例根治）（已彻底闭环）
- **背景**：此前 QQQ 期权因 20 分钟无撮合成交触发行情延迟 > 900s 一刀切门禁，导致止损意图被物理阻断锁死仓位。
- **方案实现**：
  1. 严格以 `quantity > 0` 为前置，仅平仓减仓放行，入场开仓维持最严苛门禁；
  2. 双边买卖盘口（买一卖一有效且不倒挂）+ 价差阈值（`<=20%`）校验；
  3. 价格偏离锚优化：彻底废除 `abs` 限制以保护上涨止盈平仓，改为单向校验 `bid < last` 下行偏离，阈值放宽至 `40.0%`（防止 20%~30% 正常跌幅止损被误判为闪崩）；
  4. 审计留痕与独立告警：触发时自动记录 `OPTION_EXIT_HEALTHY_BOOK_BYPASS_ACCEPTED` 并上报 `OPTION_EXIT_STALE_QUOTE_BYPASS` 告警；
  5. 参数配置化进 `Settings.load()` 与 `.env.example`；
  6. 专项测试 `test_option_exit_quality_guard.py` 10/10 全绿通过。
