# 工业级量化交易「实盘 + 模拟盘双轨并发」系统架构设计规范
> **文档版本**: 1.0 (Production Blueprint)  
> **制定日期**: 2026-10-15  
> **适用范围**: Futu OpenAPI 美股股票 + 期权全自动量化交易系统

---

## 一、背景与业务诉求

在专业量化交易与对冲基金的日常运转中，“实盘操盘”与“前沿策略/新标的孵化模拟”是一体两面的核心需求：
1. **真金白银实盘（REAL）**：仅允许经过充分验证的最成熟策略（如当前的波动率期权），在严格的风控预算铁笼（如单笔 $1,500、单日 $3,000）内受控执行真实下单与获利平仓；
2. **沙盒模拟验证（SIMULATE）**：对于大资金长周期策略（如 100 万美元的 Core Satellite 现货底仓）、新策略迭代、或处于观察期的候选卫星标的，必须在富途官方模拟盘中持续积累真实盘口成交数据、验证滑点与模型胜率；
3. **核心矛盾**：当前系统为“单通道模式（Single Gateway Channel）”，同一时刻只能在 REAL 或 SIMULATE 之间二选一，切换到实盘后模拟仓的在仓合约失去自动看管，切回模拟盘实盘又失去盯盘。

## 二、工业界主流双轨架构方案对比与选型

| 架构模式 | 实现原理 | 优点 | 缺点 | 适用场景 |
| :--- | :--- | :--- | :--- | :---: |
| **方案 A：会话动态切频 (Context Hopping)** | 单 OpenD 进程，单一服务在同一个循环里频繁切换账户查询与下单 | 无需额外进程与端口 | 易触发富途频控锁死；高频切换导致会话握手延迟高（300~800ms），极易丢失期权止盈秒级点位 | 适合低频日级别回测，**严禁用于高频/期权实盘** |
| **方案 B：独立双容器/双机隔离 (Dual Stack Deployment)** | 部署两套完全独立的系统与进程，实盘一台，模拟盘一台 | 物理级完全隔离，互不干扰 | 资源浪费；富途订阅额度翻倍消耗；无法在单一 Web 界面统一看板与对账 | 适合大型跨机构完全独立团队 |
| **方案 C（推荐选型）：双通道网关 + 共享行情总线 + 独立双执行管线 (Dual Gateway with Shared Market Bus)** | **实盘与模拟盘各占一个 OpenD 独立端口；单一行情总线统一订阅；双执行器独立接入、统一数据库账本分租户隔离** | **毫秒级并发响应；零额度浪费；风控绝对物理隔离；单一 Web 驾驶舱无缝全景掌控** | **顶层量化机构标准架构，设计最严密** | **美股高弹性期权与现货底仓最佳搭档** |

### 1. 通信与连接拓扑（端口与网关分配）
- **实盘通道（Gateway 1）**：
  - 监听本地端口：`11111`
  - 登录环境：`REAL`，锁定真实账户 `281756481476169109`；
  - 职责：只处理实盘真金白银的受控下单、挂单追价、分批止盈与真实对账。
- **模拟盘通道（Gateway 2）**：
  - 监听本地端口：`11112`
  - 登录环境：`SIMULATE`，锁定模拟账户 `20170229`；
  - 职责：处理 100 万美元模拟现货底仓再平衡、在仓 AMD 模拟期权看管与沙盒撮合。

### 2. 共享行情总线（避免订阅额度浪费）
- 富途 OpenAPI 对每类账户均有订阅额度上限（通常美股期权+正股共享 300~500 额度）；
- 双通道若各自重复订阅相同正股和期权链，额度将迅速枯竭；
- **设计**：由实盘 OpenD（11111）的 `OpenQuoteContext` 作为全局主行情网关，本地其他子策略进程（雷达、孵化器、现货再平衡）全部复用该上下文，**全局只消耗一份订阅额度，实现零冗余、高吞吐**。

### 3. 多租户账本隔离与风控绝对防火墙
- **数据库隔离**：
  - `order_intents`：每一笔意图在主键 `intent_key` 中严格携带 `:REAL` 或 `:PAPER` 后缀；
  - `equity_snapshots`：增加 `env` 列（或分表存储），彻底在底层将模拟盘 100 万美元资产快照与实盘 5.6 万美元真实资产物理拆分，**彻底杜绝任何“跨环境资产落差”引发的虚假急停**。
- **风控防火墙**：
  - 实盘风控引擎（`RealRiskEngine`）：单笔 $1,500、单日 $3,000、白名单强约束；
  - 模拟风控引擎（`PaperRiskEngine`）：独立按 100 万美元规模约束 70% 现货上限与分散度。

### 4. 前端 Web 驾驶舱双轨看板交互
在 Streamlit 首页顶部提供优雅的 **双轨并列或一键切屏（Dual Battleground Switcher）**：
- **`[🔴 实盘战区]`**：只看你的真实 3,800 美元现金、在仓期权盈亏、真实落袋止盈；
- **`[🟢 模拟战区]`**：一键切换查看 100 万美元模拟盘的 9 只股票现货底仓、模拟期权走势；
- 两边数据完全独立、各自等宽对称展示，互不干扰、井井有条！

## 四、分阶段实施路线图（明天实施计划）

明天我们可以按照以下 3 个标准步骤，从容、平稳地落地这套工业级架构：

1. **第一阶段：配置双 OpenD 网关与端口映射（约 15 分钟）**
   - 在本地配置第二份 OpenD 配置文件（`FutuOpenD.xml`），开启 `11112` 模拟盘端口；
   - 编写自动化守护启动脚本，一键拉起 `11111 (REAL)` 与 `11112 (SIMULATE)`。
2. **第二阶段：Broker 连接池多实例抽象（约 25 分钟）**
   - 将 `FutuPaperBroker` 升级为支持指定通道（`broker_real` 连 11111，`broker_sim` 连 11112）；
   - 调度器 `run_service.py` 同时派发两套独立的周期任务。
3. **第三阶段：驾驶舱双轨看板无缝呈现与验证（约 20 分钟）**
   - 首页驾驶舱提供双轨模式切换；
   - 执行端到端双向实测：验证实盘期权与模拟盘期权同时在岗盯盘，各自独立止盈！
