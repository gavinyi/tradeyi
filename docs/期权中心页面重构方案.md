# 期权中心页面重构方案

## 目标

期权策略页面同时承担标的管理、雷达扫描、候选合约、自动策略、退出参数、持仓、日志和调试，信息密度过高，用户需要长距离滚动才能完成一个任务。本次改造以行业量化平台常见的“工作台 + 任务分区 + 诊断链路”为目标，保持模拟盘交易逻辑不变，先优化信息层级，再逐步拆分代码和页面。

## 推荐的信息架构

```text
期权中心
├── 期权总览
│   ├── 账户权益 / 正股持仓 / 期权持仓 / Shadow 持仓
│   ├── 今日策略状态和异常数量
│   └── 最近执行质量与快速入口
├── 波动率期权
│   ├── 总览：监控标的、自动策略、持仓、阻断、雷达心跳
│   ├── 机会雷达：只扫描已加入的正股，自选、扫描、候选、生成策略
│   ├── 自动策略：当前持仓、开仓价、最新价、待执行、退出状态
│   ├── 参数与风控：入场、退出、分层保护、分批止盈、冷却
│   └── 执行诊断：每次决策、阻断原因、目标值、订单链路
├── 财报 Gamma
├── 期权组合执行
├── 期权盈亏台账
└── 期权数据回测
```

## 本次已落地

`pages/10_波动率期权策略.py` 已增加“策略工作台”，页面顶部先显示：

- 当前监控标的数；
- 已保存自动策略数；
- 有持仓的策略数；
- 最近阻断/异常数；
- 最近一条执行记录和中文原因；
- “今天先看 / 操作路径 / 问题排查”三个任务入口。

详细参数区默认折叠，并按“机会雷达 / 参数配置 / 自动策略 / 执行诊断”重命名；雷达结果、已保存策略、执行日志限制最大高度，避免表格无限拉长页面。已保存策略表优先展示当前持仓数、开仓价、最新价、运行状态、最新原因和配置诊断。

## 下一阶段拆分规则

## 第三轮：执行可观测性与刷新策略

总览页新增数据健康卡片，明确页面读取时间、雷达进程、券商连接和策略账本状态。页面刷新只重新读取展示数据，不会启动雷达或重复提交订单；雷达由独立服务进程负责持续运行。

后续页面统一采用以下刷新规则：

- 账户、持仓、订单：短缓存 + 手动刷新；
- 雷达状态：读取进程状态和最近扫描记录，不直接触发扫描；
- 期权链和盘口：只有用户点击“生成候选/刷新行情”时才请求；
- 历史日志、复盘和回测：使用缓存，参数变化后才重新计算。

所有显示时间统一为中国时区，并同时显示“读取时间”和“数据来源”，避免把页面打开时间误认为行情时间。

## 第四轮：筛选和移动端可读性

波动率总览的自动策略表增加代码搜索、状态筛选和“有异常”筛选；移动端默认使用精简列，只显示代码、方向、到期日、持仓、开仓价、运行状态和最新原因。关闭精简列后可查看完整字段，详细诊断仍放在交易诊断中心，避免总览表横向过宽。

## 第五轮：跨页面工作流

高级配置页顶部增加固定工作流入口：返回总览、查看执行诊断、查看期权盈亏和设置执行模式。同时显示当前执行模式、自动调度状态和交易范围，避免用户在深层页面中无法判断当前系统是否会运行。

标准工作流为：

```text
波动率策略总览 → 高级配置 → 交易诊断中心 → 期权盈亏台账
```

## 第六轮：雷达闭环诊断

总览页增加最近一次雷达扫描闭环：扫描时间、触发标的数量、自动策略生成数量、合约/风控阻断数量，以及逐标的原因。这样可以区分“没有触发”与“已触发但候选或风控不通过”，无需再从运行日志中反向拼接链路。

## 第七轮：模拟盘与 Shadow 统一视图

总览同时读取富途模拟盘持仓和 Shadow 虚拟成交账本，分别显示两类持仓策略数量，并在策略表中标注持仓来源。当前持仓和开仓价按“富途模拟盘 + Shadow”合并展示，避免策略已在 Shadow 中运行但账户页面显示为零时产生误判。

## 第八轮：复盘数据导出

总览页增加当前自动策略、雷达扫描和执行诊断的 CSV 下载。导出使用页面已读取的数据，不会因为点击下载而重复请求富途行情，文件使用 UTF-8 with BOM，Excel 打开时中文列名不乱码。

## 第九轮：一键复盘报告

在 CSV 导出旁新增 Markdown 复盘报告，自动汇总生成时间、雷达状态、监控标的、自动策略、富途/Shadow 持仓、待成交订单、最近雷达扫描和最近执行诊断。报告适合直接保存到 `docs`、提交审批或作为每日运行记录。

## 第十轮：风险优先级提示

总览页新增风险提示区，按高/中/低分级汇总券商读取失败、雷达停止、待成交订单、雷达触发后未生成策略以及 Shadow 持仓。页面打开后先看风险提示，再看策略表和详细诊断。

## 第十一轮：下一步处理队列

总览页新增“下一步处理队列”，把风险提示转换为可执行事项，按高、中、低优先级排序。队列覆盖富途连接、独立雷达、待成交订单、雷达候选阻断和 Shadow 持仓核对，并给出对应入口：订单管理、交易诊断中心、系统监控和期权盈亏台账。

雷达统计统一从决策 payload 读取 `active`、`campaign_created` 和 `campaign_reason`，避免扫描摘要与明细表使用不同字段导致数量不一致。

## 第十二轮：处理队列归档

总览页的处理队列增加高、中、低优先级数量摘要，并支持单独下载 CSV。Markdown 复盘报告同步加入“下一步处理队列”章节，使每日复盘可以直接看到需要处理的问题、原因和建议入口。

## 第十三轮：性能与可维护性

总览页将富途模拟盘持仓/订单读取封装为 15 秒短缓存，页面刷新时优先复用近期数据，减少重复访问 OpenD 造成的卡顿。持仓映射、Shadow 映射、待成交统计和 Markdown 报告生成抽成独立函数，后续继续增加导出字段或风险项时，不再把逻辑堆在页面渲染区。

## 最终收口：运营台验收

波动率策略总览补齐数据源说明、账户缓存状态、强制刷新账户缓存、表格金额/数量格式化和页面验收清单。最终目标是让总览页承担日常运营台职责：打开页面即可判断系统是否在运行、是否有策略、是否有持仓、是否有阻断、下一步处理什么，以及如何导出复盘证据。

## 高级配置页页签拆分

`波动率策略高级配置` 页内部拆为两个页签：

- 常用数据：只展示雷达状态、自动策略数量、最近执行记录、最近扫描记录、已保存策略摘要和常用入口。
- 参数配置：放置标的搜索、雷达预算、候选生成、入场参数、退出保护、分批止盈、冷却、策略清理和独立运行调试。

日常查看先停留在“常用数据”，只有需要改规则、生成候选、保存策略或批量应用参数时才进入“参数配置”。这样保留原有参数和交易逻辑，同时减少个人使用时的滚动和干扰。

### 1. 总览只做决策，不做配置

总览只保留 KPI、异常摘要、最近扫描时间、最近订单和快捷入口。所有可写参数移到“参数与风控”。

### 2. 雷达只负责发现和生成

雷达页面只处理：

1. 管理已选正股；
2. 运行扫描或查看独立雷达心跳；
3. 展示触发条件的当前值与目标值；
4. 生成并排序期权候选；
5. 将合格候选加入自动策略监控。

雷达不显示完整退出参数和历史执行日志，减少认知负担。

### 3. 自动策略只负责生命周期

自动策略页面以一行一个期权策略为核心，固定显示：正股、期权代码、方向、到期日、最新价、当前持仓、开仓价、浮盈亏、运行状态、最近原因、待成交数量。删除、清空重启和过期清理都在此页面完成。

### 4. 参数页使用表单保存

入场预算、合约筛选、退出保护、分层保护、分批止盈和冷却参数放在表单中，点击保存后一次性写入。页面明确标记“默认参数”和“已保存策略参数”，避免用户误以为只修改了新策略。

### 5. 诊断页采用事件链

每次决策按照以下链路展示：

```text
行情新鲜度 → 波动触发 → 方向判断 → 合约筛选 → IV/盘口 → 预算/组合风控
→ 下单意图 → Shadow/模拟盘撮合 → 持仓变化 → 退出原因
```

每个阻断项都同时显示当前值、目标值、是否通过和下一步建议。

## 使用路径

日常运行只需要：

1. 在“机会雷达”确认自选标的和扫描状态；
2. 在“自动策略”查看持仓、开仓价、待成交和退出状态；
3. 只有调整规则时才进入“参数与风控”；
4. 没有下单或结果异常时进入“执行诊断”。

全流程继续保持模拟盘和 Shadow 双重保护，不因页面重构自动切换实盘。

## 验收标准

- 打开波动率页面，首屏可以在 10 秒内判断“是否在扫描、是否有策略、是否有持仓、是否有阻断”；
- 不展开参数时，页面不再堆叠所有输入控件；
- 已保存策略表能直接看到持仓数、开仓价、最新价和中文原因；
- 诊断表有固定高度，可在页面内滚动查看；
- 所有保存操作仍需管理员解锁；
- Streamlit 页面检查和现有策略测试通过。
